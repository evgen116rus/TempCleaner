# TempCleaner

Консольная утилита для Windows, которая очищает временные папки и кэши. Есть две равноценные реализации: на **C#** (.NET 8) и на **C++17** (Win32 API).

## Что очищается

| Что | Путь | Действие |
|---|---|---|
| Временные файлы залогиненного пользователя | `<профиль>\AppData\Local\Temp` | содержимое очищается |
| Кэш Интернета залогиненного пользователя | `<профиль>\AppData\Local\Microsoft\Windows\INetCache` | содержимое очищается |
| Системная временная папка | `%SystemRoot%\TEMP` | содержимое очищается |
| Системная временная папка служб | `%SystemRoot%\SystemTemp` | содержимое очищается |
| Кэш Центра обновлений Windows | `%SystemRoot%\SoftwareDistribution` | содержимое очищается |
| Общая временная папка | `C:\Temp` | содержимое очищается |
| Кэш клиента SCCM / ConfigMgr | `ccmcache` (ищется автоматически) | папка удаляется целиком |

Сами папки `Temp`, `INetCache` и другие (кроме `ccmcache`) остаются, удаляется только их содержимое.

## Как это работает

### Залогиненный пользователь, а не тот, от кого запущена программа

Для работы нужны права администратора, а при запуске через UAC `%USERPROFILE%` может указывать на профиль администратора, а не на профиль того, кто работает за компьютером. Поэтому программа определяет пользователя так:

1. Через службы терминалов (WTS) берётся пользователь консольной сессии. Если в ней никого нет, берётся первая активная сессия (например, RDP).
2. По имени пользователя определяется его SID.
3. Путь к профилю читается из реестра: `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProfileList\<SID>\ProfileImagePath`.

В начале работы программа показывает, от кого она запущена и чей профиль будет очищаться. Если залогиненного пользователя найти не удалось, его папки пропускаются.

Профиль учётной записи, от которой запущена программа, не очищается (если это не тот же пользователь).

### Поиск ccmcache

Программа проверяет:
- `%SystemRoot%\ccmcache`;
- `<диск>:\ccmcache` на каждом фиксированном диске;
- `<диск>:\<любая папка>\ccmcache` на каждом фиксированном диске.

Полный обход диска не выполняется. Найденные папки удаляются целиком вместе с содержимым.

### Порядок очистки

- Файлы удаляются, предварительно снимается атрибут «только чтение».
- Подпапки обрабатываются рекурсивно, пустые подпапки удаляются.
- Файлы, занятые другими процессами, и места без доступа пропускаются. Они не останавливают программу и считаются в статистике.
- Символические ссылки и junction не обходятся, удаляется только сама ссылка. Это защищает от выхода за пределы очищаемой папки.
- Корень диска никогда не очищается: такие пути отклоняются.
- В конце выводится статистика по каждой папке и общий итог: сколько файлов и папок удалено, сколько места освобождено, сколько элементов пропущено.

## Использование

```
TempCleaner.exe              спросит имя компьютера или файл со списком, затем очистка с подтверждением
TempCleaner.exe --list pc.txt  очистка компьютеров из списка через pse.exe (без вопроса об имени)
TempCleaner.exe --service ps_tc  имя службы PsExec на удалённом ПК (по умолчанию ps_tc)
TempCleaner.exe --dry-run    пробный запуск: показать, что будет удалено, ничего не удаляя
TempCleaner.exe --yes        очистка этого компьютера без вопросов (для планировщика задач)
TempCleaner.exe --no-pause   не ждать нажатия клавиши в конце
```

Перед первой очисткой рекомендуется запустить с `--dry-run`.

## Удалённый запуск

После запуска программа спрашивает:

```
Имя компьютера или файл со списком (Enter - этот компьютер):
```

- **Enter (пусто)**: очистка выполняется на этом компьютере.
- **Имя компьютера** (например `PC-0123` или `pc-0123.corp.local`): очистка выполняется на удалённом компьютере через PsExec.
- **Путь к текстовому файлу** (например `C:\lists\pc.txt`): очистка выполняется по очереди на всех компьютерах из файла. Путь можно перетащить мышью в окно консоли.

Вопрос не задаётся при запуске с `--yes` или `--no-pause`, поэтому запуск по расписанию не зависает.

### Список компьютеров из файла

Файл содержит по одному имени компьютера в строке:

```
# Бухгалтерия
PC-0101
PC-0102
\\PC-0103
pc-0104.corp.local
; эта строка тоже комментарий
```

- Пустые строки и строки, начинающиеся с `#` или `;`, игнорируются.
- Допускается запись вида `\\PC-0103`. Повторяющиеся имена удаляются.
- Кодировка файла: UTF-8 (с BOM или без), UTF-16 или ANSI.
- Список можно передать и параметром: `TempCleaner.exe --list C:\lists\pc.txt`. Вопрос об имени при этом не задаётся.
- Перед запуском программа показывает список и один раз спрашивает подтверждение для всех компьютеров (при `--yes` и `--dry-run` не спрашивает).
- Компьютеры обрабатываются по очереди. Ошибка на одном (недоступен, нет прав) не останавливает остальные.
- В конце выводится сводка: сколько компьютеров обработано успешно и список компьютеров с ошибками и кодами завершения.
- Пример запуска по расписанию для списка: `TempCleaner.exe --list C:\lists\pc.txt --yes --no-pause`.

### Как это работает

Программа вызывает переименованный PsExec (`pse.exe`) примерно так:

```
pse.exe \\PC-0123 -accepteula -nobanner -n 15 -r ps_tc -s -c -f TempCleaner.exe --yes --no-pause
```

- `-c -f`: PsExec копирует `TempCleaner.exe` на удалённый компьютер (в `ADMIN$`) и запускает его там, по завершении копия удаляется.
- `-s`: программа работает от учётной записи SYSTEM.
- `-r ps_tc`: служба PsExec на удалённом компьютере создаётся под именем `ps_tc`, а не под стандартным `PSEXESVC`. Это помогает там, где защита блокирует службу по её стандартному имени. Своё имя задаётся параметром `--service` (латинские буквы, цифры, `_` и `-`, до 64 символов).
- `-n 15`: ожидание подключения не дольше 15 секунд.
- `--yes --no-pause`: на удалённой стороне программа работает без вопросов. Подтверждение запрашивается один раз локально, перед запуском (при `--dry-run` не запрашивается).
- Вывод удалённой программы отображается в вашей консоли.
- Залогиненный пользователь определяется уже на удалённом компьютере (через WTS), поэтому очищаются `Temp` и `INetCache` того, кто там работает. Если на удалённом компьютере никто не залогинен, эти папки пропускаются, системные папки очищаются в любом случае.

`pse.exe` ищется в таком порядке: рядом с программой, в текущей папке, в `PATH`.

### Требования для удалённого запуска

- Ваша учётная запись (в домене, как правило доменный администратор) должна быть локальным администратором на удалённом компьютере. Отдельные логин и пароль не передаются.
- На удалённом компьютере должны быть доступны сетевой ресурс `ADMIN$` и SMB (порт 445): включены общий доступ к файлам и принтерам и разрешение в брандмауэре.
- Копируемая программа должна работать без установки дополнительных компонентов:
  - **C++-версия** при сборке с `/MT` ничего не требует и весит мало. Для удалённого запуска она предпочтительнее.
  - **C#-версии** нужен .NET 8 Runtime на удалённом компьютере. Если его нет, соберите автономную версию: `dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true`. Такой файл весит около 70 МБ, и копирование займёт больше времени.

## Требования

- Windows 10 / 11 / Server.
- Права администратора. Запрос UAC встроен в приложение (манифест).
- Для C#-версии нужен .NET 8 Runtime. C++-версия при сборке с `/MT` ничего устанавливать не требует.
- Для удалённого запуска нужен `pse.exe` (переименованный PsExec из Sysinternals) рядом с программой или в `PATH`.

## Сборка

### C#

```
cd TempCleaner
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

Файлы проекта: `Program.cs`, `TempCleaner.csproj`, `app.manifest`.

### C++

В «Developer Command Prompt for VS» (MSVC):

```
cl /std:c++17 /EHsc /O2 /MT /utf-8 TempCleaner.cpp
```

Флаг `/utf-8` нужен для корректной компиляции русских строк. Запрос прав администратора задан в самом коде через `#pragma comment(linker, ...)`, поэтому с MinGW он не работает: там exe нужно запускать «от имени администратора».

## Важно

- **Удаление необратимо**: файлы не попадают в корзину.
- Закройте запущенные программы перед очисткой: они могут держать во временных папках рабочие файлы. Занятые файлы будут пропущены, но закрытие программ повышает эффективность очистки.
- **ccmcache**: файлы кэша могут быть заняты службой `CcmExec`. Тогда папка удалится не полностью, о чём программа сообщит. Перед очисткой можно остановить службу (`net stop CcmExec`). Клиент SCCM сам пересоздаст кэш и при необходимости скачает пакеты заново.
- **SoftwareDistribution**: здесь Windows хранит загруженные обновления. Пока работают службы Центра обновлений (`wuauserv`) и BITS, часть файлов занята и будет пропущена. Для полной очистки остановите их (`net stop wuauserv` и `net stop bits`) и запустите службы после очистки (`net start wuauserv` и `net start bits`). После очистки Windows заново создаст журнал обновлений, и первая проверка обновлений может занять больше времени.
- Путь `C:\Temp` задан буквально. Если системный диск у вас не `C:`, измените его в коде.
- Программа предназначена для обслуживания рабочих станций. Используйте её на свой риск и сначала проверьте с `--dry-run`.
