# TempCleaner

Консольная утилита для Windows, которая очищает временные папки и кэши. Есть две равноценные реализации: на **C#** (.NET 8) и на **C++17** (Win32 API).

## Что очищается

| Что | Путь | Действие |
|---|---|---|
| Временные файлы залогиненного пользователя | `<профиль>\AppData\Local\Temp` | содержимое очищается |
| Кэш Интернета залогиненного пользователя | `<профиль>\AppData\Local\Microsoft\Windows\INetCache` | содержимое очищается |
| Системная временная папка | `%SystemRoot%\TEMP` | содержимое очищается |
| Системная временная папка служб | `%SystemRoot%\SystemTemp` | содержимое очищается |
| Общая временная папка | `C:\Temp` | содержимое очищается |
| Кэш клиента SCCM / ConfigMgr | `ccmcache` (ищется автоматически) | папка удаляется целиком |

Сами папки `Temp`, `INetCache` и другие (кроме `ccmcache`) остаются, удаляется только их содержимое.

## Как это работает

### Залогиненный пользователь, а не тот, от кого запущена программа

Для работы нужны права администратора, а при запуске через UAC `%USERPROFILE%` может указывать на профиль администратора, а не на профиль того, кто работает за компьютером. Поэтому программа определяет пользователя так:

1. Через службы терминалов (WTS) берётся пользователь консольной сессии. Если в ней никого нет, берётся первая активная сессия (например, RDP).
2. По имени пользователя определяется его SID.
3. Путь к профилю читается из реестра: `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProfileList\<SID>\ProfileImagePath`.

В начале работы программа показывает, от кого она запущена и чей профиль будет очищаться. Если залогиненного пользователя найти не удалось, его папки пропускаются.

Профиль учётной записи, от которой запущена программа, не очищается (если это не тот же пользователь).

### Поиск ccmcache

Программа проверяет:
- `%SystemRoot%\ccmcache`;
- `<диск>:\ccmcache` на каждом фиксированном диске;
- `<диск>:\<любая папка>\ccmcache` на каждом фиксированном диске.

Полный обход диска не выполняется. Найденные папки удаляются целиком вместе с содержимым.

### Порядок очистки

- Файлы удаляются, предварительно снимается атрибут «только чтение».
- Подпапки обрабатываются рекурсивно, пустые подпапки удаляются.
- Файлы, занятые другими процессами, и места без доступа пропускаются. Они не останавливают программу и считаются в статистике.
- Символические ссылки и junction не обходятся, удаляется только сама ссылка. Это защищает от выхода за пределы очищаемой папки.
- Корень диска никогда не очищается: такие пути отклоняются.
- В конце выводится статистика по каждой папке и общий итог: сколько файлов и папок удалено, сколько места освобождено, сколько элементов пропущено.

## Использование

```
TempCleaner.exe              очистка с запросом подтверждения
TempCleaner.exe --dry-run    пробный запуск: показать, что будет удалено, ничего не удаляя
TempCleaner.exe --yes        очистка без вопросов (для планировщика задач)
```

Перед первой очисткой рекомендуется запустить с `--dry-run`.

## Требования

- Windows 10 / 11 / Server.
- Права администратора. Запрос UAC встроен в приложение (манифест).
- Для C#-версии нужен .NET 8 Runtime. C++-версия при сборке с `/MT` ничего устанавливать не требует.

## Сборка

### C#

```
cd TempCleaner
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

Файлы проекта: `Program.cs`, `TempCleaner.csproj`, `app.manifest`.

### C++

В «Developer Command Prompt for VS» (MSVC):

```
cl /std:c++17 /EHsc /O2 /MT /utf-8 TempCleaner.cpp
```

Флаг `/utf-8` нужен для корректной компиляции русских строк. Запрос прав администратора задан в самом коде через `#pragma comment(linker, ...)`, поэтому с MinGW он не работает: там exe нужно запускать «от имени администратора».

## Важно

- **Удаление необратимо**: файлы не попадают в корзину.
- Закройте запущенные программы перед очисткой: они могут держать во временных папках рабочие файлы. Занятые файлы будут пропущены, но закрытие программ повышает эффективность очистки.
- **ccmcache**: файлы кэша могут быть заняты службой `CcmExec`. Тогда папка удалится не полностью, о чём программа сообщит. Перед очисткой можно остановить службу (`net stop CcmExec`). Клиент SCCM сам пересоздаст кэш и при необходимости скачает пакеты заново.
- Путь `C:\Temp` задан буквально. Если системный диск у вас не `C:`, измените его в коде.
- Программа предназначена для обслуживания рабочих станций. Используйте её на свой риск и сначала проверьте с `--dry-run`.
